# Bug & Defect Tracker
## Common Ground — Café E-Commerce & Order Management Platform

Every defect below was discovered through direct code inspection and runtime testing during Phase 1–3.

| Issue ID | Severity | Affected Module(s) | Description | Root Cause | Fix & Verification | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **BUG-001** | **Critical** | `js/pages/checkout.js` | Shopping bag (`cartService`) is not cleared after placing an order on Checkout. | `checkout.js` submit handler redirects to `tracking.html` after `submitOrderToBackend()` without calling `cartService.clear()`. | Call `cartService.clear()` immediately after order creation; verified by E2E checkout test. | **Fixed & Verified** |
| **BUG-002** | **High** | `server/routes/api.js` | Public order tracking endpoint `GET /api/orders/track/:reference` exposes full customer phone, email, and street address on sequential order IDs (IDOR / PII leak). | `GET /api/orders/track/:reference` returned raw `loadFullOrder()` output intended for authenticated staff. | Added `sanitizePublicTrackingOrder()` masking phone/email/street on public tracking while preserving full details on authenticated `/api/orders/:id` and `/api/admin/orders`. Verified by security test suite. | **Fixed & Verified** |
| **BUG-003** | **High** | `js/pages/admin.js`, `server/routes/api.js` | Stored XSS vector in Admin Console tables (`Customers`, `Discounts`, `Staff`, `Orders`) and unsanitized HTML tags in order inputs. | `js/pages/admin.js` used `innerHTML` with unescaped template literals for `fullName`, `email`, `code`, `description`; backend did not strip HTML tags from customer inputs. | Replaced unsafe `innerHTML` with safe DOM text nodes / `escapeHtml()` in `js/pages/admin.js` and added server-side HTML tag stripping on customer inputs. Verified by XSS unit/integration test. | **Fixed & Verified** |
| **BUG-004** | **High** | `server/routes/api.js` | N+1 SQL query bottleneck in `GET /api/admin/orders` (`201` queries for 50 orders) and `fetchCustomizationGroupsForProduct`. | `GET /api/admin/orders` looped over order IDs calling `loadFullOrder()`, which looped over items querying `order_item_customizations`. | Implemented `loadFullOrdersBatch()` using 3 batched `ANY($1)` SQL queries regardless of order/item count, and batched `fetchCustomizationGroupsForProduct` into 2 queries. Verified by query-count performance benchmark. | **Fixed & Verified** |
| **BUG-005** | **Medium** | `js/pages/checkout.js`, `server/routes/api.js`, `js/services/apiClient.js` | Checkout promo code validation used a hardcoded client dictionary (`COFFEEONUS` = 30 EGP) that disagreed with PostgreSQL (`COFFEEONUS` = 50 EGP, min 200 EGP) and ignored Admin-created coupons. | Missing `/api/coupons/validate` endpoint; `checkout.js` relied on local `PROMO_CODES` constant. | Added `POST /api/coupons/validate` endpoint (plus fallback in `apiClient.js`) and wired `checkout.js` to validate coupons against the authoritative database rules. Verified by coupon validation tests. | **Fixed & Verified** |
| **BUG-006** | **Medium** | `server/routes/api.js` | Duplicate order creation on rapid double-submission or network retry of `POST /api/orders`. | No idempotency key or short-window fingerprint deduplication on `POST /api/orders`. | Added `Idempotency-Key` header / payload support and 15-second order fingerprint deduplication returning the existing order without double-deducting inventory. Verified by concurrent/duplicate submission test. | **Fixed & Verified** |
| **BUG-007** | **Medium** | `js/pages/menu.js`, `js/components/productCard.js` | Sold-out products display an active `+ Add` button that silently does nothing when clicked. | `createMenuCard()` and `createProductCard()` did not check `product.available` when rendering the action button and badge. | Render `SOLD OUT` badge and disable the action button (`Sold out`, `disabled = true`) when `!product.available`. Verified by UI & unit tests. | **Fixed & Verified** |
| **BUG-008** | **Medium** | `server/utils/crypto.js` | JWT signing secret checked `process.env.AUTH_TOKEN_SECRET` but ignored `process.env.JWT_SECRET` documented in `.env.example` and `DEPLOYMENT_GUIDE.md`. | Inconsistent environment variable name between `crypto.js` and deployment configuration. | Updated `crypto.js` to resolve `process.env.JWT_SECRET || process.env.AUTH_TOKEN_SECRET` dynamically. Verified by token verification test. | **Fixed & Verified** |
| **BUG-009** | **Low** | `server/services/telegramService.js` | Unescaped Markdown characters (`_`, `*`, `` ` ``) in customer instructions can cause Telegram `sendMessage` HTTP 400 parse errors. | Raw user strings interpolated directly into legacy Telegram Markdown message template. | Added `escapeTelegramMarkdown()`, deduplication set for notified order references, and safe error handling. Verified by unit test. | **Fixed & Verified** |
| **BUG-010** | **Low** | `js/pages/admin.js`, `server/routes/api.js` | Admin Analytics tab displayed static HTML values instead of hydrating from `GET /api/admin/analytics`. | `loadAllAdminData()` did not call `/api/admin/analytics` or render dynamic analytics data. | Added `renderAnalyticsSection()` in `js/pages/admin.js` and enriched `GET /api/admin/analytics` with live database metrics. Verified by Admin API & UI test. | **Fixed & Verified** |
